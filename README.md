# Лабораторная работа: Акустический канал утечки информации

Учебный репозиторий по дисциплине **«Технические каналы утечки информации»**.
Работа выполняется на оригинальном проекте
[`ggerganov/kbd-audio`](https://github.com/ggerganov/kbd-audio).

Скрипт `install.sh` собирает `kbd-audio` и устанавливает все его
бинарники в `/usr/local/bin`, а данные n-грамм — в
`/usr/local/share/kbd-audio/data`. После установки все инструменты
доступны по имени из любого каталога.

---

## 1. Цель и задачи

**Цель** — практически подтвердить возможность утечки вводимой с
клавиатуры информации по акустическому каналу, освоить инструментарий
`kbd-audio` и количественно оценить зависимость достоверности
восстановления текста от условий наблюдения.

**Задачи:**

1. Развернуть стенд одной командой.
2. Зафиксировать физическую природу акустического канала утечки:
   каждый тип клавиши создаёт кратковременный переходный процесс с
   повторяемой спектральной структурой.
3. Собрать набор аудиоданных и применить детектор нажатий.
4. Получить численную оценку точности распознавания для режимов
   `keytap` и `keytap3`.
5. Построить зависимость точности от типа клавиатуры, расстояния,
   уровня фонового шума и объёма обучающей выборки.
6. Выполнить расчётные задания: ОСШ, вероятность правильного
   распознавания, энтропия, взаимная информация, кривая обучения,
   расстояние Левенштейна.
7. Сформулировать рекомендации по снижению риска канала утечки.

**Конечный результат** — отчёт с численными значениями точности и
графиками зависимостей, подтверждающими (или опровергающими)
практическую реализуемость акустического канала утечки в исследованных
условиях.

## 2. Требования к стенду

| Компонент | Требование |

| Гипервизор | VirtualBox, VMware Workstation Player или аналог |

| Права | `sudo` для записи в `/usr/local/bin` и `/opt` |

## 3. Развёртывание стенда

```bash
git clone https://github.com/ORG/kbd-audio-lab.git
cd kbd-audio-lab
sudo ./install.sh
```

(замените `ORG` на имя организации-владельца репозитория)

Скрипт выполняет:

1. проверку окружения (команды, SDL2, микрофон);
2. установку системных зависимостей;
3. клонирование оригинального `https://github.com/ggerganov/kbd-audio`
   в `/opt/kbd-audio/src`;
4. сборку (`cmake` + `make`);
5. установку бинарников в `/usr/local/bin`;
6. копирование данных n-грамм в `/usr/local/share/kbd-audio/data`.

Повторный запуск безопасен: уже выполненные шаги пропускаются.

## 4. Порядок выполнения работы

### Шаг 0. Калибровка условий

1. Зафиксируйте расстояние от микрофона до клавиатуры (20, 50, 100 см).
2. Зафиксируйте уровень фонового шума (по индикатору записи).
3. Выберите тестовый текст (30–50 символов; язык — как в n-граммах
   `/usr/local/share/kbd-audio/data`).
4. Определите набор клавиш для обучения (10–15 символов, включая пробел).

### Шаг 1. Запись обучающей выборки

```bash
mkdir -p ~/kbd-lab/data ~/kbd-lab/results
record ~/kbd-lab/data/train_mech_20.kbd
```

Напечатайте последовательность, в которой каждая целевая клавиша
встречается не менее 5–10 раз. Завершение — `Ctrl+C`.

Повторите для мембранной клавиатуры:

```bash
record ~/kbd-lab/data/train_memb_20.kbd
```

### Шаг 2. Визуальный анализ

```bash
view-gui ~/kbd-lab/data/train_mech_20.kbd
```

Зафиксируйте среднюю длительность переходного процесса, наличие
второго пика и различия сигналов разных клавиш. Скриншоты сохраните
в `~/kbd-lab/results/screenshots/`.

### Шаг 3. Распознавание с обучением (`keytap`)

```bash
keytap ~/kbd-lab/data/train_mech_20.kbd | tee ~/kbd-lab/results/keytap_mech_20.log
```

Напечатайте тестовый текст, не входящий в обучающую выборку. Лог
предсказаний — `~/kbd-lab/results/keytap_mech_20.log`.

Повторите для мембранной клавиатуры и других расстояний.

### Шаг 4. Распознавание без обучения (`keytap3`)

```bash
record-full ~/kbd-lab/data/test_full.kbd
keytap3 ~/kbd-lab/data/test_full.kbd /usr/local/share/kbd-audio/data \
    | tee ~/kbd-lab/results/keytap3_test_full.txt
```

Восстановленный текст — `~/kbd-lab/results/keytap3_test_full.txt`.

### Шаг 5. Расчёт метрик

Все расчёты выполняются по формулам из раздела 5. Их удобно считать
в LibreOffice Calc, Excel или скриптом на Python — на выбор студента.
Шаблон отчёта — `templates/report.md`.

## 5. Расчётные задания для групп

Все формулы записаны в виде обычного текста, чтобы одинаково
отображаться в любом просмотрщике Markdown.

### Задание 1. Отношение сигнал/шум (ОСШ)

```
ОСШ [дБ] = 10 * lg ( P_сигнала / P_шума )
```

где:

- `P_сигнала` — средняя мощность на интервалах нажатий;
- `P_шума`    — средняя мощность на интервалах пауз.

Запишите фоновый шум (5–10 с без нажатий), затем несколько нажатий
одной клавиши. Вычислите среднюю мощность сигнала и шума, рассчитайте
ОСШ. Повторите для расстояний 20, 50, 100 см и для двух уровней шума.

**Сдать:** таблицу ОСШ по конфигурациям и вывод о пороге, при
котором точность резко падает.

### Задание 2. Точность и матрица ошибок

```
P_прав = N_прав / N_общ * 100 %

M[i][j] = n[i][j] / n[i]
```

где:

- `N_прав` — число правильно распознанных нажатий;
- `N_общ`  — общее число нажатий в тестовом тексте;
- `n[i][j]` — число случаев, когда истинной клавише `i` предсказана `j`;
- `n[i]`    — общее число нажатий клавиши `i`;
- `K`       — число различных клавиш в тесте; матрица имеет размер `K x K`.

По логу `keytap` составьте матрицу ошибок. Оцените долю ошибок типа
«соседняя клавиша» и предложите две гипотезы, объясняющие это явление.

### Задание 3. Энтропия и взаимная информация

```
H(X)    = - СУММА ( p(x_i) * log2 p(x_i) )
H(X|Y)  = - СУММА ( p(x_i, y_j) * log2 p(x_i | y_j) )
I(X;Y)  = H(X) - H(X|Y)
```

где:

- `p(x_i)`        — вероятность символа `x_i` в языке (или в тексте);
- `p(x_i, y_j)`   — совместная вероятность истинного `x_i` и
                    наблюдаемого `y_j` (по матрице ошибок);
- `p(x_i | y_j)`  — условная вероятность (по матрице ошибок).

Оцените `H(X)` по частотам символов, `H(X|Y)` — по матрице ошибок,
`I(X;Y)` — в битах на символ.

### Задание 4. Кривая обучения

```
P_прав(n) ~= P_max * (1 - exp(-n / n0))
```

где:

- `n`     — число обучающих примеров на клавишу;
- `P_max` — предельная точность при n -> бесконечность;
- `n0`    — характерное число примеров.

Постройте экспериментальную зависимость точности от числа обучающих
примеров на клавишу (1, 2, 3, 5, 10) и оцените `P_max` и `n0`
методом наименьших квадратов. Сделайте вывод о минимальном числе
примеров для достижения точности 80 %.

### Задание 5. Доля ошибочных символов и слов (`keytap3`)

```
ДОС  = d_симв(S_ист, S_восст) / max(|S_ист|, |S_восст|) * 100 %
ДОСл = d_слов(W_ист, W_восст) / max(|W_ист|, |W_восст|) * 100 %
P_симв = (1 - ДОС) * 100 %
```

где:

- `d_симв` — расстояние Левенштейна по символам;
- `d_слов` — расстояние Левенштейна по словам;
- `S_ист`, `S_восст` — истинная и восстановленная строки;
- `W_ист`, `W_восст` — списки слов истинной и восстановленной строк.

## 9. Возможные проблемы

- **`command not found` после `install.sh`.** Убедитесь, что
  `/usr/local/bin` есть в `$PATH` (`echo $PATH`). Обычно он там по
  умолчанию; если нет — добавьте в `~/.profile`:
  `export PATH=/usr/local/bin:$PATH`.
- **`arecord -l` не видит микрофон.** Включите проброс аудио в
  гипервизоре; пользователь должен входить в группу `audio`.
- **`keytap3` падает с ошибкой данных.** Проверьте, что каталог
  `/usr/local/share/kbd-audio/data` существует. Переустановка:
  `sudo ./install.sh`.
- **Низкая точность `keytap`.** Увеличьте число обучающих примеров на
  клавишу (5–10) и уменьшите фоновый шум.
