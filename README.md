# Лабораторная работа: Акустический канал утечки информации

Учебный репозиторий по дисциплине **«Технические каналы утечки информации»**.
Работа выполняется на оригинальном проекте
[`ggerganov/kbd-audio`](https://github.com/ggerganov/kbd-audio).

Скрипт `install.sh` собирает `kbd-audio` и устанавливает все его
бинарники в `/usr/local/bin`, а данные n-грамм — в
`/usr/local/share/kbd-audio/data`. После установки все инструменты
доступны по имени из любого каталога.

Скрипт `check.sh` проверяет, что стенд установлен правильно.

---

## 1. Цель и задачи

**Цель** — практически подтвердить возможность утечки вводимой с
клавиатуры информации по акустическому каналу, освоить инструментарий
`kbd-audio` и количественно оценить зависимость достоверности
восстановления текста от условий наблюдения.

**Задачи:**

1. Развернуть стенд и убедиться в его работоспособности.
2. Собрать наборы аудиоданных на мембранной клавиатуре в режимах с
   обучением и без обучения.
3. Выполнить распознавание при разных условиях: расстояние до
   микрофона, уровень фонового шума, объём обучающей выборки.
4. Рассчитать по приведённым ниже формулам метрики для оценки
   достоверности восстановления текста.
5. Построить зависимости метрик от условий наблюдения и сопоставить
   экспериментальные результаты с теоретическими оценками.
6. Сформулировать обоснованные рекомендации по снижению риска
   акустического канала утечки.

**Конечный результат** — отчёт с численными значениями метрик и
графиками зависимостей, обосновывающими (или опровергающими)
практическую реализуемость акустического канала утечки в исследованных
условиях.

Расчёты студенты выполняют самостоятельно: вручную, в табличном
редакторе или собственным скриптом на любом удобном языке. Готового
скрипта для расчётов в репозитории нет.

## 3. Развёртывание стенда

```bash
git clone https://github.com/imnazipov/kbd-audio-lab
cd kbd-audio-lab
sudo ./install.sh
./check.sh
```

`install.sh` выполняет:

1. проверку окружения;
2. установку системных зависимостей;
3. клонирование `https://github.com/ggerganov/kbd-audio` в `/opt/kbd-audio/src`;
4. сборку `cmake` + `make`;
5. установку бинарников в `/usr/local/bin`;
6. копирование n-грамм в `/usr/local/share/kbd-audio/data`.

`check.sh` проверяет:

- наличие всех бинарников `kbd-audio` в `$PATH`;
- наличие и непустоту каталога с n-граммами;
- системные зависимости (`git`, `cmake`, `make`, `gcc`, `SDL2`, `arecord`);
- доступность микрофона;
- наличие Python (для возможных расчётов);
- каталоги `~/kbd-lab/data` и `~/kbd-lab/results`.

Если что-то не так — скрипт подскажет, что именно и как исправить.

## 4. Инструменты `kbd-audio` и их назначение

После установки доступны (оригинальные, без оберток):

| Бинарник | Назначение |
|---|---|
| `record <file>` | Запись в момент нажатий клавиш (обучающая выборка) |
| `record-full <file>` | Непрерывная запись (для `keytap3`) |
| `view-gui <file>` | Просмотр осциллограмм записанных данных |
| `view-full-gui <file>` | Просмотр непрерывной записи |
| `keytap <train-file>` | Распознавание с обучением (по эталонам) |
| `keytap2-gui`, `keytap3 <file> <data>` | Распознавание без обучения (по языковой модели) |

Данные n-грамм для `keytap3` — в `/usr/local/share/kbd-audio/data`.

## 5. Порядок выполнения работы

### Шаг 0. Калибровка условий

1. Зафиксируйте расстояние от микрофона до клавиатуры: 20, 50, 100 см.
2. Зафиксируйте уровень фонового шума в аудитории (тихо и шум).
3. Выберите тестовый текст (30–50 символов). Язык текста должен
   совпадать с языком n-грамм в `/usr/local/share/kbd-audio/data`.
4. Определите набор клавиш для обучения в режиме `keytap`
   (10–15 различных символов, включая пробел).

Подготовьте каталоги для данных и результатов:

```bash
mkdir -p ~/kbd-lab/data ~/kbd-lab/results
```


### Шаг 1. Запись обучающей выборки

```bash
record ~/kbd-lab/data/train_memb_20.kbd
```

Напечатайте последовательность, в которой каждая целевая клавиша
встречается не менее 5–10 раз. Завершение записи — `Ctrl+C`.

Повторите для каждого выбранного расстояния: `train_memb_50.kbd`,
`train_memb_100.kbd`.

### Шаг 2. Визуальный анализ

```bash
view-gui ~/kbd-lab/data/train_memb_20.kbd
```

Зафиксируйте для отчёта:

- среднюю длительность переходного процесса нажатия;
- наличие второго пика (отпускание клавиши);
- визуальные различия сигналов разных клавиш;
- как меняется амплитуда и форма сигнала с ростом расстояния.

Скриншоты характерных осциллограмм сохраните в
`~/kbd-lab/results/screenshots/`.

### Шаг 3. Распознавание с обучением (`keytap`)

```bash
keytap ~/kbd-lab/data/train_memb_20.kbd | tee ~/kbd-lab/results/keytap_memb_20.log
```

Напечатайте тестовый текст, не входящий в обучающую выборку.
Программа выводит предсказанные клавиши в реальном времени.

Повторите для всех выбранных расстояний и для двух уровней фонового
шума (тихо и шум). Имена логов: `keytap_memb_<dist>_<noise>.log`.

### Шаг 4. Распознавание без обучения (`keytap3`)

```bash
record-full ~/kbd-lab/data/test_full_memb.kbd
keytap3 ~/kbd-lab/data/test_full_memb.kbd /usr/local/share/kbd-audio/data \
    | tee ~/kbd-lab/results/keytap3_memb.txt
```

Восстановленный текст сохраняется в файл. Сравните его с истинным.
Повторите для разных расстояний и при фоновом шуме.

### Шаг 5. Обработка результатов

По формулам из раздела 6 рассчитайте метрики для каждой конфигурации
эксперимента и постройте требуемые зависимости.

## 6. Формулы для расчётов

Ниже приведены формулы, которые необходимо применить. Если для
какой-то метрики нужен иной, более подходящий способ расчёта —
обоснуйте его в отчёте.

### 6.1. Отношение сигнал/шум (ОСШ)

```
ОСШ [дБ] = 10 * lg ( P_сигнала / P_шума )
```

где:

- `P_сигнала` — средняя мощность на интервалах нажатий;
- `P_шума`    — средняя мощность на интервалах пауз между нажатиями.

Мощность — среднее квадратов амплитуд на выбранном интервале. Способ
разделения сигнала и шума (например, по порогу амплитуды) выберите и
обоснуйте сами.

### 6.2. Точность распознавания с обучением

```
P_прав = N_прав / N_общ * 100 %
```

где:

- `N_прав` — число правильно распознанных нажатий;
- `N_общ`  — общее число нажатий в тестовом тексте.

### 6.3. Матрица ошибок

```
M[i][j] = n[i][j] / n[i]
```

где:

- `n[i][j]` — число случаев, когда истинной клавише `i` предсказана `j`;
- `n[i]`    — общее число нажатий клавиши `i`;
- `K`       — число различных клавиш в тесте; матрица имеет размер `K x K`.

Дополнительно определите:

```
P_сосед = N_сосед / N_ош * 100 %
```

где `N_сосед` — число ошибок, при которых предсказанная клавиша
является соседней на физической раскладке, `N_ош` — общее число
ошибок.

### 6.4. Энтропия и взаимная информация

```
H(X)   = - СУММА ( p(x_i) * log2 p(x_i) )
H(X|Y) = - СУММА ( p(x_i, y_j) * log2 p(x_i | y_j) )
I(X;Y) = H(X) - H(X|Y)
```

где:

- `p(x_i)`        — вероятность символа `x_i` в языке (или в тестовом
                    тексте);
- `p(x_i, y_j)`   — совместная вероятность истинного `x_i` и
                    наблюдаемого `y_j` (по матрице ошибок);
- `p(x_i | y_j)`  — условная вероятность (по матрице ошибок).

Значения — в битах на символ.

### 6.5. Кривая обучения

```
P_прав(n) ~= P_max * (1 - exp(-n / n0))
```

где:

- `n`     — число обучающих примеров на клавишу;
- `P_max` — предельная точность при n -> бесконечность;
- `n0`    — характерное число примеров.

Оцените `P_max` и `n0` (например, методом наименьших квадратов или
подбором). Определите минимальное `n`, при котором достигается
точность 80 %:

```
n_80 = - n0 * ln( 1 - 0.8 / P_max )
```

Формула применима при `P_max > 0.8`.

### 6.6. Доля ошибочных символов и слов (`keytap3`)

```
ДОС  = d_симв(S_ист, S_восст) / max(|S_ист|, |S_восст|) * 100 %
ДОСл = d_слов(W_ист, W_восст) / max(|W_ист|, |W_восст|) * 100 %
P_симв = (1 - ДОС) * 100 %
```

где:

- `d_симв` — расстояние Левенштейна по символам;
- `d_слов` — расстояние Левенштейна по словам;
- `S_ист`, `S_восст` — истинная и восстановленная строки;
- `W_ист`, `W_восст` — списки слов истинной и восстановленной строк.

Расстояние Левенштейна — минимальное число вставок, удалений и замен
символов (или слов), переводящее одну строку в другую.

## 9. Возможные проблемы

- **`command not found` после установки.** Проверьте, что
  `/usr/local/bin` есть в `$PATH` (`echo $PATH`). Если нет — добавьте
  в `~/.profile`: `export PATH=/usr/local/bin:$PATH`.
- **`arecord -l` не видит микрофон.** Включите проброс аудио в
  гипервизоре; добавьте пользователя в группу `audio`.
- **`keytap3` падает с ошибкой данных.** Проверьте, что каталог
  `/usr/local/share/kbd-audio/data` существует, переустановите через
  `sudo ./install.sh`.
- **Низкая точность `keytap`.** Увеличьте число обучающих примеров
  на клавишу (5–10) и уменьшите фоновый шум.

Проверка установки в любой момент:

```bash
./check.sh
```
